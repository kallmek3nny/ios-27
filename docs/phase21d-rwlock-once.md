# phase 21d: bounded rwlock and once bridge

Original-source synchronization bridge, independently built and tested. This is **not** a claim that Linux `pthread_rwlock_t` or `pthread_once_t` shares the Darwin binary layout, nor that Apple frameworks can execute unchanged. No emulator, system root changes, Apple binaries, or edits to shared build metadata.

## implemented guarantees

1. Bounded pool of 1..256 generational objects, with runtime-scoped monotonic cookies that reject handles from other runtimes; stale handles, invalid kinds and exhaustion are rejected deterministically; generation wrap permanently retires a slot rather than reviving an ancient handle (`EINVAL` or `EAGAIN`). Failed construction never publishes a valid handle. Destruction rejects held or queued locks and once initializers/waiters (`EBUSY`). No lock is destroyed while a waiting thread has a stack-allocated queue entry.
2. Reader-writer lock built from an original FIFO wait queue protected by one runtime mutex. Consecutive readers are admitted together. Once any writer waits, later readers cannot barge ahead. Writers cannot be overtaken by readers and readers cannot be overtaken by subsequent writers. Writer ownership and per-thread reader ownership are checked; wrong-owner unlock is `EPERM`, same-thread recursion and upgrades return `EDEADLK`, try-lock contention returns `EBUSY`. Resource exhaustion of the reader-owner allocation returns `ENOMEM`. Bounded absolute `CLOCK_REALTIME` timed reader/writer waits validate signed 64-bit nanosecond deadlines, remove expired waiters atomically without disturbing queued successors, and return `ETIMEDOUT` without an acquired lock; a confirmed grant wins a simultaneous timeout race.
3. Once initialization publishes completion after the initializer returns zero. Nonzero error rolls back to uninitialized, wakes waiters, and permits retry. Negative callback results violate the positive POSIX-error contract and are normalized to `EINVAL` after rollback. Same-thread reentrancy and a bounded cross-thread initialization dependency cycle return `EDEADLK`. Nested acyclic initialization is supported. A guarded condition-variable broadcast and waiter accounting prevent missed completion and destruction-before-wakeup. Host cancellation is temporarily disabled for queue and initializer safety.

## limitations / integration boundaries

The API accepts opaque bridge handles and is **not** a drop-in Darwin pthread ABI. A future guest-object translation layer must validate Darwin pthread layouts and translate guest pointers before calling these bridge functions. The Clang-produced ARM64 C, Objective-C, and Objective-C++ Mach-O tests demonstrate genuine Darwin-target compiler callsites and Objective-C class metadata, not native execution of Darwin code or dynamic linking against libSystem. No fair scheduling guarantee can be made if an owner never releases or the OS indefinitely starves a runnable thread. A thread exiting while holding a lock is a caller error. The runtime must not be destroyed concurrently with new calls; join or stop all callers first. Initializers must return normally (no longjmp or pthread_exit). Cancellation is disabled through each internal critical bridge operation and once callback. The caller remains responsible for unlocking before a subsequent cancellation point. Asynchronous pthread cancellation of a lock-holder is unsupported. This does not detect cycles involving unrelated user locks.

## independent verification

`timeout 180s python3 tools/phase21d-standalone.py` builds at `-O0` and `-O2` with `-Werror`, runs eight compiled native integration programs, seven of them multithreaded testing 470,400 reader/writer acquisitions across 2,400 native workers, plus 57,600 shared-map operations from 48 concurrent reader/writer agents sharing a single once-initialized 64-bucket dataset, 8,000 generation reuse cycles, FIFO writer-before-reader ordering, 12 simultaneous readers, invalid ownership, exhaustion, 64 concurrent once callsites, nested ordering, 2-thread once cycles and 1,500 failed-initializer retries; 320 timed-lock contention/timeout cycles, queued timeout removal, non-barging timed readers, cancellation deferral including failed-initializer rollback, full 256-slot pool validation, 2,048 runtime cookie lifecycles, cross-thread reader-owner rejection, injected malloc exhaustion, condition-variable construction/destruction rollback, host condition-variable failures (including after admission), spurious wakeups and grant/timeout races, and 60 three-way and 30 32-thread once initialization dependency cycles. It emits genuine `arm64-apple-darwin` Clang Mach-O C, Objective-C, and Objective-C++ objects, and verifies bridge-handle layout under the target ABI. `PHASE21D_SANITIZE=1` additionally runs ASan/UBSan and `PHASE21D_TSAN=1` runs ThreadSanitizer. The fault-injection test uses GNU linker symbol wrapping on Linux hosts; production code remains unchanged. The dedicated CI workflow runs the standard `-O0`/`-O2` suite on both hosts and then runs ASan/UBSan and TSan on x86_64 with `PHASE21D_SKIP_BASE=1` to avoid redundant unsanitized test runs. The skip flag is rejected unless a sanitizer is selected. Separate CI tests x86_64 and arm64 hosts; this does not modify CMake or the repository-wide test matrix.

## cumulative code coverage

`timeout 180s python3 tools/phase21d-coverage.py` builds one GCC gcov-instrumented bridge object, links all eight real compiled tests into their own executables, then collects cumulative production-source coverage. Local verification measured **98.60% lines, 87.29% branch outcomes**. CI requires at least 90% lines and 70% branch outcomes, allowing minor compiler-version differences. The unexecuted production lines require exhaustion of a 64-bit monotonic runtime-cookie counter or corruption of the guarded once dependency graph; they are defensive fail-closed branches.

### deterministic fifo cohort regression

The standalone harness also runs `tests/phase21d-fairness.c`. Each of 25
rounds queues 16 writers while a reader holds the lock, then verifies exact
fifo admission. A separate queue admits three readers together, then a writer,
then three later readers; the test confirms that neither reader cohort can
bypass the queued writer. All wait loops are bounded and the whole program is
run under the independent build and sanitizer variants.
