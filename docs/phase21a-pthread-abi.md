# phase 21a: Darwin pthread ABI boundary

This is an original-source, standalone, opt-in bridge. It is **not** Apple's libpthread and is not currently integrated into the production loader.

## three milestones

1. **ABI envelopes:** 64-bit Darwin mutex (64 bytes), condition (48), rwlock (200), once (16), attribute (64), and opaque attribute records. The fixed layouts are statically asserted on Clang's real `arm64-apple-darwin` target. None contain Linux pthread types.
2. **Guest boundaries:** all guest pointers are translated through up to eight immutable, permissioned, caller-owned guest regions, never raw host pointers. Validate address underflow, span, alignment, access permissions, region-straddling and overflow before touching memory. Guest and host mapping aliases are rejected. 128 synchronized host slots manage separate mutex/condition/rwlock/once/attribute objects with signature and generation tokens, safe slot pinning and deterministic EFAULT, EINVAL, EBUSY, EAGAIN paths. Stale, copied and corrupted records fail closed.
3. **Symbols and verification:** explicit allowlist of pthread mutex, condition and rwlock operations. Unknown exports return ENOSYS. Supported symbols validate arguments; mutex attributes support init/destroy/gettype/settype and recursive locking without a Linux attribute layout cast. Trusted callback registrations (max 32) allow race-safe once initialization with bounded retry; no raw guest PC is executable. Explicit guest thread bindings (max 64 unique addresses) implement pthread_self and pthread_equal without leaking host pthread_t. Bridge-generated TLS keys (max 64) support pthread_key_create/delete, getspecific and setspecific for attached threads; non-null guest destructors fail closed with ENOTSUP. Unsupported condition/rwlock attributes and arbitrary guest callbacks return ENOTSUP. Native contention tests, recursive attributes, real condition waits/timed waits, once initializer races, guest pthread identity and TLS, malformed output alias rejection, permissioned multi-region translation, exhaustion, 10,000 reuse cycles, deterministic failure cases, and structurally verified Clang-generated ARM64 Darwin Mach-O objects with true undefined pthread nlist entries and ARM64 BRANCH26 relocations run under independent x86_64 and arm64 CI.

Run: `timeout 180s python3 tools/phase21a-standalone.py`. ASan/UBSan: `PHASE21A_SANITIZE=1 timeout 180s python3 tools/phase21a-standalone.py`.

## explicitly unsupported

pthread_create/join/detach, cancellation, guest-executable function callbacks, TLS destructors, workqueues, process-shared attributes and dynamic scheduling remain unsupported. pthread_once only invokes explicitly registered trusted host callback functions. pthread_self/equal use explicitly bound guest identities, and TLS requires such bindings. These are controlled bridge approximations, not full Darwin thread ABI. Known Darwin normal/error-checking/recursive mutex, condition and rwlock static initializers are lazily materialized only after validating their zero-filled opaque bytes. The native-error-checking default is a safe compatibility approximation. The signatures used for live objects are bridge-private, not Apple-internal signatures. Backing host regions must remain stable and exclusively managed, with no guest-side concurrent writes outside the bridge; immutable mapping permissions are policy checks, not hardware isolation. This bridge is not yet a hardened guest memory system. Host ERRORCHECK mutex semantics are deliberately not claimed identical to Darwin's default mutex. No Apple binaries, SDKs, emulation or bootloader operations used.

## return conventions and incomplete ABI integration

* `ios27_21a_call` uses x0..x5 unsigned 64-bit AArch64 argument cells, and writes the guest x0 scalar. For error-returning pthread APIs, this is the errno value; for `pthread_self`, `pthread_equal`, and `pthread_getspecific` it is a guest pointer/boolean/value. The host function result is a bridge status, **not** a Darwin syscall errno channel.
* Guest `pthread_t` values must be registered as mapped guest addresses by trusted code using `ios27_21a_attach_thread`. Detach is explicit, clears that binding's TLS, and permanently tombstones its address until runtime destruction to avoid stale-value reuse. The bridge does not create an actual Darwin `struct pthread` or Mach thread.
* Unknown guest destructor or callback pointers are never called. Caller-managed host callback registrations for `pthread_once` must return normally and must not transfer control out with `longjmp` or thread exit. `ios27_21a_release_once` is an explicit host teardown API, **not** a Darwin `pthread_once_destroy`.
* Absolute guest `timespec` input is decoded little-endian, requires a mapped read region, and uses the host CLOCK_REALTIME condition variable while a verified single-depth mutex is held. More clock variations and process-shared semantics are unsupported.
* No dynamically loaded Apple libSystem, arm64e pointer authentication, kernel workqueues, full pthread lifecycle, TLS destructor callbacks, or production dyld activation is claimed.
